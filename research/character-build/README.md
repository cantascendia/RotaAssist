# 角色技能、天赋与 build 上下文

2026-09-22，Astra 实现。对应 rc.8。新增的是角色观测与策略适用性基础，
不是已经校准所有天赋效果的伤害模拟器，也没有读取到本机真实玩家的角色。

## 已接入产品

- 枚举活动配置的天赋树和节点，记录选择项、等级、定义 ID、技能 ID、英雄子树。
  未选分支不计入已选天赋；只有完整扫描过的天赋技能才可证明等级为零。
  同一技能在多个已选节点出现时，其合并等级保留未知。
- 拒绝尚未提交的编辑、secret/错误/不完整读取，并在结束时复查活动配置、
  专精和编辑状态。所选节点和等级排序组成确定性的天赋标识。
- 记录装备 ID 与规范 item token，保留附魔、宝石和其他修饰字段。物品存在
  但链接未缓存时标记装备不完整，不当作空槽。不同语言的显示名称不参与标识。
- 读取循环相关及所选天赋技能的已学状态、施法时间、射程、基础冷却，以及
  可证明的单一平坦最低资源费用。冷却和费用标明采样语义，不强行应用到所有
  后续施法，也没有从 tooltip 猜测伤害系数。
- 急速、暴击、精通效果、攻击强度与可读全能分别采样。属性相关事件只刷新
  属性，不重扫天赋；不可读时清除旧值。属性采样时间与修订号单独保留。
- APL 英雄配置识别使用这份完整快照。独立决策新增 `talent.<技能ID>.rank`
  事实支持；没有有效角色配置时保留默认建议路径，不采用实验独立首位。
- 天赋、专精、装备、已学技能变化会清空旧参考缓存、独立诊断、首位和预测
  队列。`/ra build` 提供中英日诊断与公开的天赋导入字符串。

当前已有冻结策略未因此自动变成每个 build 的最优策略。英雄配置识别仍按
既有数值签名匹配；新天赋等级条件支持是引擎能力，不能冒充全部天赋已建模。
装备身份和角色属性也尚未连接到完整技能伤害系数模型。

## 跨 build 反例实验

使用同一固定 SimC 引擎/提交，分别下载固定提交的两个官方 Havoc 配置。
在每个配置内比较其原策略和强制套用当前邪痕策略。两套配置可能同时有装备
差异，所以只比较表格每一行内部，不把不同行 DPS 差归因于单一天赋。
种子 20261002，单体/五目标，120 秒，2 线程，每次请求 2000、实际 1999 样本。
共 8 次运行、15,992 个样本。

| 官方 build | 敌人数 | 强制使用当前邪痕策略，相对该 build 自带策略 |
|---|---:|---:|
| Fel-Scarred | 1 | -1.40% |
| Fel-Scarred | 5 | -1.41% |
| Aldrachi Reaver | 1 | -38.87% |
| Aldrachi Reaver | 5 | -41.95% |

奥达奇两行是**故意错配的反例**；现有运行时英雄配置检查本来就应拒绝这种
错配，本轮加强完整配置和失效处理，不能声称新修复使真实玩家提升了 40%。
实验说明一套技能策略不能代表所有浩劫 build。它不是用户角色 DPS 测量，
也不是两个英雄天赋之间的强弱排名。源码仍包含 Rune of Unleashed Fire 的
目标假设。完整参数、原始输出哈希与逐行策略在
[build-sensitivity.json](build-sensitivity.json)。

## 证据和剩余工作

[API 固定来源及哈希](sources.json)使用 Blizzard 生成文档的 Gethe 镜像，
提交 `78282522143e25c3540583734fd192c3d69be910`。核心依据包括
[Trait 节点与配置 API](https://github.com/Gethe/wow-ui-source/blob/78282522143e25c3540583734fd192c3d69be910/Interface/AddOns/Blizzard_APIDocumentationGenerated/SharedTraitsDocumentation.lua)
以及 [ClassTalents API](https://github.com/Gethe/wow-ui-source/blob/78282522143e25c3540583734fd192c3d69be910/Interface/AddOns/Blizzard_APIDocumentationGenerated/ClassTalentsDocumentation.lua)。

666 Lua、79 Python（含训练解析器）通过；165 addon Lua 文件通过语法检查。
新增 7 个故障注入全部被行为测试检出。Hypothesis 检验天赋枚举顺序不影响
标识，并保留每个选择的等级。参见 [verification.json](verification.json)。

仍需真实客户端确认接口读取覆盖率、事件时序和每次刷新耗时；需要实际角色
的装备/天赋配置来建立对应伤害模型，并校准费用、增伤、触发、目标命中和
短期动作收益。配置完整标识只表明观测一致，不是最高 DPS 的认证。
